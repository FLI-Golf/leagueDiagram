# Production checklist and final file naming convention

This document is the final operating checklist for the approved three-part demo series. Use it as the gating document before any final render, review, or MP4 cleanup.

---

## 1) Approved story and screens

### Part 1 — League Admin setup
- Screen flow:
  - app load
  - Mock current user visible
  - switch account to League Admin
  - confirm active account
  - open Manage league
  - review Create upcoming season form
  - inspect Season name, Purse amount, Title sponsor name
  - scroll to Season setup & tournaments
- Approved narration:
  - "Welcome to LeagueDiagram. We are starting from the league admin view, where the season setup is already partly mapped out. We switch accounts to League Admin and confirm the active user is now in the admin role. From the dashboard, we open Manage league and review the Create upcoming season form. The season name is already prepared, the purse amount is set, and the title sponsor is populated for us. Scrolling down, we see the rest of the season setup and tournament structure, including the upcoming tournament schedule and the timing details that keep the league ready for launch. This screen shows how the platform brings the campaign, the budget, and the calendar together before the season goes live."

### Part 2 — Fantasy owner draft
- Screen flow:
  - app load
  - Mock current user visible
  - switch account to Fantasy Owner
  - open Fantasy league
  - seed fantasy draft
  - start draft
  - view Round 1 · Pick 1
  - highlight recommended pro and draft clock
  - allow auto-picks to progress
  - end on standings or progression view
- Approved narration:
  - "Now we switch to the Fantasy Owner role, where the league experience becomes more interactive. We open the Fantasy league screen and seed the draft so the system can build the player pool and schedule the upcoming picks. Once the draft is live, we see the opening board with Round 1 and Pick 1, and the recommended selections are highlighted to help the owner make informed choices. The draft clock is running, and the system continues to auto-pick through the live round, so the board evolves naturally as the draft progresses. This is the moment where strategy, player value, and real-time league flow come together inside one view. By the end of the sequence, the draft has unfolded and the standings reflect the decisions that were made."

### Part 3 — Switch to Fantasy Owner and seed the draft
- Screen flow:
  - app load
  - Mock current user visible
  - use the Signed in as dropdown and select Fantasy Owner
  - click Switch account
  - scroll down
  - click Seed fantasy draft
  - scroll through the draft interface in sections
  - reveal the tournament, round, pick, on-the-clock state, timer, and next-up player
- Approved narration:
  - "Now we switch to the Fantasy Owner account and confirm the role change. In this mock demo, we seed the fantasy league with participants to show how the FLI Golf fantasy draft works. We scroll down and seed the draft, then move through the draft interface section by section to show the tournament we are drafting and the live draft order. Fantasy Owner is on the clock with no picks yet, and Taylor Reed is next up. We then highlight the remaining draft order cards, showing each participant's current state before the first pick is made. This is the opening draft board, and it clearly shows who is on the clock and who is next in the turn order."

---

## 2) Production checklist

Before moving on to final approval, confirm all of the following:

- [ ] The narration matches the visible UI and action sequence.
- [ ] No sentence references a screen that is not part of the capture.
- [ ] The sequence opens and closes on the correct state for the part.
- [ ] The draft or season progress is consistent with the actual app state.
- [ ] The active account and role match the narration.
- [ ] The timestamped pacing feels natural and not rushed.
- [ ] The cursor, pointer movement, and highlights are clean and readable.
- [ ] The recording contains no duplicate scenes or accidental extra actions.
- [ ] There is only one approved master render per part.
- [ ] All alternate versions are archived or removed before final delivery.

---

## 3) Final file naming convention

Use this naming format for the approved production files.

### Folder layout
- demo/narrated/part-1/
- demo/narrated/part-2/
- demo/narrated/part-3/

### File naming
- part-1-approved-narration.mp3
- part-1-approved-final.mp4
- part-2-approved-narration.mp3
- part-2-approved-final.mp4
- part-3-approved-narration.mp3
- part-3-approved-final.mp4

### Optional archive naming
Only use archive names for rejected drafts.
- part-1-archive-v1.mp4
- part-1-archive-v2.mp4
- part-2-archive-v1.mp4
- part-3-archive-v1.mp4

### Do not use
Avoid naming that creates confusion or signals multiple “final” versions.
- final-final
- final-cut
- scene-aligned
- cinematic
- voice-*
- merged-version
- intro-final-final
- outro-final-final

---

## 4) Delivery rule

Only the following files are considered deliverables:
- one approved audio file per part
- one approved MP4 per part
- one approved narration sheet

Everything else is treated as working draft or archive material.

---

## 5) Final approval gate

A part is approved only when:
- the script is checked against the Playwright capture,
- the screen progression matches the narration exactly,
- the file name follows the approved convention,
- and no alternate duplicate render is left as a primary deliverable.
